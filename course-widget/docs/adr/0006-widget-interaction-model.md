# 挂件交互模型：14 个加号 + 手动移动/缩放，其余穿透

- 状态：已实施（2026-08-02）
- 相关：ADR-0001（不嵌入壁纸层）

## Context
v2 挂件是"固定角落 + 整格日期可点"，日期格/空白区只要划过就会切成交互，仍会挡到桌面图标的点击。用户希望交互面越小越好：只有日期格右上角的加号、移动手柄、缩放手柄、右上角按钮可点，其余全部穿透到桌面图标；并希望挂件可自由摆放、宽高可手动拖，去掉随内容自动调整高度。

## Decision
1. **选择性交互**：点击穿透判定只保留 `.add`（14 个日期加号）、`.mv`（移动手柄）、`.rz`（四边四角缩放手柄）、`button`（隐藏/设置按钮）。
2. **自由摆放**：左上角手柄拖动窗口；位置持久化到 `widgetX/widgetY`；删除原 `moved` 事件的"自动吸回角落"逻辑。
3. **手动缩放**：四边四角拖拽改宽高；移除 `scheduleResize` 自动高度；首次启动（未持久化高度）按内容一次性定高后冻结；宽高持久化到 `widgetWidth/widgetHeight`。
4. **拖拽保护**：拖拽期间暂停点击穿透切换，用 `setPointerCapture` + document 级 pointermove/pointerup 兜底。
5. 设置页的"角落下拉"（此前是未绑定的死控件）替换为"贴到右下角/右上角"归位按钮（`widget:snapCorner`，复用 `anchorPos`）。

## Consequences
- 空白处鼠标事件 100% 落到桌面图标/桌面，只有 14+1+8+2 个控件可交互，遮挡面最小。
- 挂件不再"贴死"角落，但保留一键归位能力；用户可自由摆放。
- 高度不再自适应内容：窗口过矮时内容被裁（`overflow:hidden`），由用户自行调大。
- 移除了遗留的 `embedIntoWallpaper` 调用（托盘"显示桌面挂件"曾误触发壁纸嵌入，违反 ADR-0001 的结论）。
